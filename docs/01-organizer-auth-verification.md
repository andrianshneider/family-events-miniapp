# 01 — Авторизация Organizer → Мои события

Среда: существующие `family-events-staging`, `FamilyEventsMiniAppBot` и Vercel `family-events-miniapp`. Ветка: `infrastructure-foundation`. Production и main не изменяются.

## Реализация

- Mini App отправляет исходный SDK initData на сервер. HMAC, структура, отсутствие дублированных полей и свежесть до 300 секунд проверяются до установления личности. Новая миграция `202610100005_mini_app_logins.sql` атомарно закрепляет digest за сессией: повтор без этой действующей сессии отклоняется, повтор в ней возвращает тот же токен. Перестановка параметров защиту не обходит. Исходный initData не хранится.
- Web/PWA использует существующий OIDC Authorization Code Flow: PKCE S256, state cookie, одноразовая серверная транзакция, nonce, RS256/JWKS, issuer, audience и expiry. Подписанный `profile.id`, а не `sub` или username, находит того же `app.users.telegram_user_id`, что и Mini App. Отмена/ошибка возвращает на `/login` с русским сообщением.
- Сессия восстанавливается сервером по HttpOnly/Secure/SameSite=Lax cookie, имеет абсолютный срок 30 дней; logout отзывает её и требует Origin/CSRF. При возврате приложения из фона и восстановлении страницы из browser back cache профиль и события повторно проверяются через сервер. Токены не хранятся в localStorage.
- `/api/v1/events` определяет владельца только по сессии, исключает soft-deleted события и возвращает ограниченную проекцию. Пагинация по `(event_date,id)` даёт все записи через «Показать ещё»; cursor не влияет на владельца. Неверный cursor → 422. Ответы приватные, без кеширования.
- UI сохраняет русский язык, safe area, мобильную адаптацию и инструкции установки на iPhone; есть загрузка, empty state, ошибка и повтор. Создание/редактирование и приватная страница отдельного события пока отсутствуют. HTML в public — сохранённые справочные макеты; рабочие 01/02 перенаправляют в Next.js.

## Автоматическая проверка

`tests/organizer-slice.test.ts` исполняет настоящие route handlers и сервисы на PostgreSQL (PGlite) с runtime-ролью `fe_server`. Подменяются транспорт Telegram и хранилище HTTP cookies, но JWT подписывается тестовым ключом и проверяется настоящим verifier.

Проверены: поддельный/устаревший/некорректный initData; replay и повтор в той же сессии; OIDC PKCE и однократное использование state; оба входа → один user; пустой список; 104 неудалённых события в двух страницах без дублей; игнорирование чужого organizer_id; запрет чужого события в существующем DAL; no-store; восстановление токена повторным запросом; expiry; отзыв предыдущей сессии; CSRF и logout.

`tests/oidc.test.ts` дополнительно проверяет несовпадение nonce/audience/issuer, истёкший токен, чужую подпись, отсутствие/несовпадение state cookie, неподтверждённые ID и повтор транзакции. `scripts/auth-smoke.ts` проверяет развёрнутый staging с синтетическими подписанными payload, временными пользователями/событиями и удалением только собственных fixtures. Скрипт запрещает запуск на другом домене/проекте БД. Синтетический smoke не доказывает реальный вход Telegram.

## Проверка реальным пользователем — обязательна перед полной приёмкой

1. Открыть Mini App через `@FamilyEventsMiniAppBot`, войти, убедиться в экране «Мои события». Для нового аккаунта — «У вас пока нет событий». Обновить и заново открыть Mini App: вход сохраняется.
2. Открыть `https://family-events-staging.vercel.app` в Safari, войти тем же аккаунтом через Telegram. Через `/api/v1/me` в авторизованном браузере можно сверить внутренний `data.id`; не передавать cookies, initData или токены. Если есть события, их набор совпадает.
3. Добавить сайт на экран «Домой» iPhone, запустить с иконки. При необходимости войти заново: Telegram должен вернуть именно в установленное приложение с «Моими событиями». Отдельное окно Safari без авторизованной PWA не является успешной проверкой возврата. Закрыть PWA и открыть снова; проверить сохранение входа.
4. Выйти: открытие `/events` и refresh возвращают к входу. Войти снова. Отменить следующий OIDC-вход: отображается сообщение и доступна повторная попытка.
5. Сообщить результат отдельно для Mini App, Safari и установленной PWA, а также версию iOS. При проблеме описать, где открылся callback; не присылать URL с `code`/`state`.

Проверка установленной PWA требует настоящего iPhone. Полная приёмка остаётся открытой до результатов реального устройства. Встроенный браузер в текущей сессии отказал в доступе из-за недоступной проверки административной политики; ограничение не обходилось.

## Исправление повторного входа после выхода в Mini App

При logout Telegram сохраняет initData текущего окна, а приложение отзывает сессию. Защита от replay ранее блокировала повторный вход. Миграция 006 добавляет hash одноразового разрешения: CSRF-защищённый logout выдаёт его только в HttpOnly/Secure cookie браузера, уже владевшего этой Mini App сессией. Разрешение привязано к receipt, подтверждённому user и отозванной сессии; само по себе не даёт доступа к API. Вход атомарно потребляет его и выдаёт новую сессию. Подпись и предел свежести initData в 300 секунд остаются обязательными. Повтор без разрешения или с уже использованным разрешением отклоняется.

Если initData старше пяти минут, нужно закрыть Mini App и открыть через бота, чтобы получить свежие данные Telegram. Экран теперь явно объясняет действие и содержит кнопку закрытия Mini App. Локальная PostgreSQL-проверка покрывает logout → немедленный повторный вход, отзыв старого токена, неверное/повторно использованное разрешение и сохранение запрета просроченного initData. Hosted smoke расширен этим же сценарием.

## Safari: начало входа и возвращение из Telegram

Кнопка Web/PWA теперь является обычной same-origin ссылкой на существующий OIDC start: она не ждёт загрузки Mini App SDK, работает без клиентского обработчика и не остаётся в состоянии «Входим…» при navigation. Mini App по-прежнему перехватывает действие и отправляет initData серверу. При возврате на login из фона либо browser back cache `/api/v1/me` перепроверяет сессию и переводит авторизованного пользователя в `/events`. Проверка имеет timeout; ошибка сети не блокирует повторный вход.

Зависание страницы `oauth.telegram.org` и перевод активного приложения с Telegram на Safari находятся вне контроля Family Events. Изменение не обещает автоматического foreground-переключения приложений iOS. Фактический provider flow требует повторной проверки на iPhone; пользовательский дефект полностью закрытым не считается.
