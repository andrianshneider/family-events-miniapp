## Реализация

- `/events/new` защищён серверной сессией. Форма: обязательные название/тип/дата, необязательные время/место/адрес/описание/dress code/обложка, timezone, desktop preview, safe area, отмена с подтверждением и Telegram BackButton.
- `POST /api/v1/events`: principal из сессии, Origin/CSRF, strict input, IANA/DST и дата в timezone события. Existing `idempotent` сохраняет результат в одной транзакции с Event, одним Wishlist (surprise ON) и analytics `event_created`. Дата проверяется внутри новой операции, поэтому безопасный replay уже созданного события не ломается на следующий день.
- `/events/{id}` и `GET /api/v1/events/{id}` проверяют владельца и soft deletion. Неизвестный/чужой/удалённый объект одинаково недоступен. Приватный DTO не содержит идентичности бронирующих гостей. Summary берётся из БД; это ответы, а не число приглашённых.
- Реальные сведения и обложка доступны после refresh; карточки списка ведут на правильные UUID. Страницы динамические; API no-store. Старый 03 HTML перенаправляется в рабочую форму; старый 04 без внутреннего UUID — в список. Справочные HTML сохранены.
- Обложка использует existing signed upload + complete, перекодирование WebP и снятие EXIF. Прикрепление только `ready` asset владельца. Ошибка сохраняет прежний выбор; поля можно заполнять во время загрузки. Новые owner-protected preview/cover API выдают signed redirect на 60 секунд: большой файл загружается непосредственно из private Storage, без лимита тела ответа serverless. Signed URL не записывается в Event или временную форму. Next Image использует `unoptimized`, поскольку проверка требует cookie браузера.
- Временная форма хранит только разрешённые поля, userId, timestamp и ключ/тело неопределённого запроса в localStorage, на один час. Это не Event draft в БД и не кеш приватных API. Другая личность/истёкший срок/некорректный snapshot отвергаются. Auth/CSRF tokens не сохраняются. После успеха или подтверждённой отмены snapshot удаляется. При недоступном browser storage форма остаётся только в памяти; восстановление после закрытия тогда не подтверждено.
- После неопределённого ответа поля блокируются; «Проверить создание» использует прежний key/payload. Подтверждённая 403/422/429 позволяет исправить поля. Повторный вход возвращает в `/events/new` по точному allowlist; при открытии приложения заново список предлагает продолжить временную форму. Ни восстановление, ни авторизация не отправляют её автоматически. Перед мутацией проверяется совпадение аккаунта.

Визуальные взаимодействия и размеры экрана не считаются проверенными по одному HTML-ответу. В этой сессии computer-use inventory сообщил недоступность browser backend; реальный iPhone/PWA и визуальная проверка остаются отдельными пунктами приёмки.

## Сценарий для пользователя после обновления staging

1. В Mini App открыть «Создать событие». Ожидание: пустая форма по экрану 03, тип не выбран, зона показана, отправка неактивна до обязательных полей.
2. Ввести только название, тип и сегодняшнюю/будущую дату. Создать. Ожидание: «Событие создано», правильная страница, пустой вишлист и нулевые ответы, без выдуманных времени/адреса.
3. Вернуться в список, обновить, открыть карточку и обновить страницу события. Ожидание: тот же объект и сведения.
4. Создать второе событие с изображением и всеми полями. Во время загрузки дописать описание. Ожидание: текст не теряется, обложка и переносы сохраняются, дата/часы/timezone совпадают.
5. Начать третью форму; отменить и выбрать продолжение, затем отменить с выходом. Ожидание: первый вариант сохраняет поля, второй очищает форму и не создаёт событие. Проверить Telegram BackButton.
6. Отключить сеть во время заполнения. Ожидание: поля доступны, отправка отключена; после восстановления — можно создать. После неопределённого результата — «Проверить создание», не новый пустой запрос.
7. В Safari и установленной PWA повторить минимум и обложку. Проверить клавиатуру, прокрутку, safe area и возврат к списку. Особенности возврата после Telegram остаются как в срезе 01.
8. В Safari заполнить новую форму. В другой вкладке того же Safari открыть «Мои события» и нажать «Выйти». Вернуться в форму: серверная проверка должна отправить к входу. После входа тем же аккаунтом — восстановленные поля без автоматической отправки. Это проверка отзыва, без ожидания 30 дней и без передачи cookies/initData/tokens.

Полная приёмка ожидает результатов реального устройства и визуального QA; технические результаты staging будут записаны после hosted smoke.
