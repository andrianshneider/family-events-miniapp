# Проверка производительности staging — 11 октября 2026

Опубликованная реализация: `6df496d`, Vercel Preview https://vercel.com/ast-dbae/family-events-miniapp/BoVUa7XwuvET53jdPPrqTjpx7K9T. Сайт: https://family-events-staging.vercel.app. Исходная версия: `8caa8ae`. Production и main не менялись.

## Изменения

1. Функции Vercel закреплены в `fra1` рядом с Supabase Frankfurt; HTTP-заголовки подтверждают `arn1::fra1` вместо `arn1::iad1`.
2. Профиль и события приходят в серверном HTML. Проверка сессии объединена с чтением профиля; первая страница списка загружается общим сервисом. Начальные клиентские `/me` и `/events` удалены. Фоновый API отдаёт профиль вместе со списком.
3. Обновление сохраняет карточки, объединяет одновременные запросы и подавляет повторные события восстановления в течение секунды. 401 очищает список и возвращает на вход. Короткоживущие ссылки обновляются раз в 90 секунд при видимом приложении.
4. Новые загрузки получают WebP-миниатюры до 640×384, quality 72, без метаданных. Две существовавшие ready-обложки обработаны без изменения оригиналов. Все миниатюры остаются в приватном bucket; cleanup удаляет обе версии. Разрешённые владельцу пути подписываются одной пакетной операцией на 120 секунд, исключая запрос к приложению для каждой картинки. При ошибке подписания используется защищённый endpoint оригинала. Ссылки — краткоживущие bearer capabilities, как и ранее для оригиналов; публичного доступа bucket не добавляли.
5. Request-local измерения `session`, `events_db`, `storage_sign`, `total`: API возвращает `Server-Timing`, сервер пишет числовые метрики без персональных данных и URL в `performance` logs. Для SSR используются серверные logs.

## Методика

Один и тот же временный Organizer, событие и синтетическое WebP-изображение 1200×800 на одном staging-host. Один прогрев и пять измерений для каждой версии, одинаковый клиент и последовательность запросов. В таблице — медиана пяти измерений; прогрев исключён.

«Открытие списка с данными» до = сумма времени получения HTML, `/me`, `/events`, потому что реальный экран выполнял эти этапы последовательно. После = время получения полного HTML, уже содержащего профиль и событие. «Обновление списка» до = `/me` + `/events`, после = один `/events`. Остальные API измерены напрямую. Обложка измеряется по URL, реально возвращённому списком: оригинал через защищённый redirect до, прямая signed thumbnail после.

Это сетевые/серверные измерения, а не LCP, DOM paint или замеры физического iPhone. Обложка искусственно шумная и результат уменьшения её размера не следует переносить на все пользовательские фотографии. Пять повторов не дают надёжного p95. Все сырые безопасные измерения сохранены в before.json и after.json.

| Сценарий | До | После | Сокращение | Прирост скорости |
|---|---:|---:|---:|---:|
| Открытие списка с данными | 1913 мс | 316 мс | 83.5% | +505.4% |
| Обновление списка | 1367 мс | 287 мс | 79.0% | +376.3% |
| API профиля | 676 мс | 215 мс | 68.2% | +214.4% |
| API событий | 683 мс | 287 мс | 58.0% | +138.0% |
| Загрузка обложки | 1182 мс | 496 мс | 58.0% | +138.3% |
| Размер обложки, байт | 718786 байт | 81850 байт | 88.6% | — |

Сокращение = `(1 − после/до) × 100%`. Прирост скорости = `(до/после − 1) × 100%`. Для размера файла показывается только сокращение.

Первый запрос в серии: 4551 → 2175 мс для получения данных первого экрана; это не доказательство измерения cold start. В повторной серии один HTML-ответ занял 1123 мс, остальные 286–415 мс. Поэтому мгновенный ответ во всех обстоятельствах не гарантируется.

## Проверки

- Типы, линтер, production build; 29 автоматических тестов прошли, включая изоляцию владельцев, пагинацию, SSR без начальных клиентских запросов, пакетную выдачу ссылок, ограничение размеров миниатюр и изоляцию метрик между конкурентными запросами.
- Hosted auth smoke: подпись initData, отклонение подделок/просроченных/replay, cookies, профиль, реальное чтение событий, пагинация, чужой владелец, refresh, истечение сессии, CSRF, выход/relogin.
- Hosted create/edit smoke: создание, редактирование, замена/удаление обложки, реальные upload и миниатюры, идемпотентность, конфликт версий, CSRF и чужой владелец. Все тестовые файлы и записи удалены.
- Hosted infrastructure smoke: реальная БД/schema/Storage/DAL с откатом.
- В браузере с существующей сессией пользователя рабочий список открыт; во время ручного обновления карточки остались видимыми, после завершения сохранены. Чужие данные, пароли и токены не извлекались.
- Performance fixture, session и Storage-объекты удалены после замеров.
- Отдельная физическая проверка iPhone PWA в этом запуске не выполнялась.
